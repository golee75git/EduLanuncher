# HANDOFF — 다른 PC·다른 Cursor에서 이어가기

기준일: 2026-09-24  
저장소: https://github.com/golee75git/EduLanuncher  
브랜치: `main`  
최신 커밋 시점의 앱 버전: `0.1.178-20261006`

지원 종료 표는 해마다 새 버전 출시 때 갱신 필요, 출처: Microsoft Windows 11 release information. 표는 `src-tauri/src/security_judge.rs`의 `SUPPORT_ENDS`이다. 날짜가 비어 있으면 그 버전은 확인 불가다. Windows 11 25H2 칸은 비어 있다.

웹뷰 침해 시 스토어 플러그인으로 tools.json의 실행 대상을 바꿀 수 있음. 막으려면 도구 추가·수정을 Rust 명령으로 옮기고 store 쓰기 권한을 줄여야 함. CSP가 1차 방어선.

## 보안 4단계

등록소 용도와 상한 (`src-tauri/src/path_grant.rs`): 읽기 128, 쓰기 32, 개인정보 검사 200, 결과 위치 열기 800, 실행 800, 문서 검색 폴더 64. 개인정보 검사는 상한에서 거부하고, 나머지는 가장 오래된 번호를 잊는다.

번호 재사용: 문서 검색·사용자 폴더 검색·즐겨찾기 목록의 열기 번호는 그 목록이 보이는 동안 다시 쓸 수 있다. 새 검색, 검색을 비움, 화면을 떠나면 그 묶음만 지운다. 고른 파일의 읽기·쓰기 번호와 고른 직후 한 번용 실행 번호는 성공하면 지운다. 문서 검색 폴더 번호는 목록을 다시 읽을 때 갈아끼운다.

허용 창: 실행, 검색 결과 열기, 폴더 열기, 문서·사용자 폴더·즐겨찾기 검색, 문서 검색 폴더 추가·제거, 단축키, 패널 위치는 메인 창만. 업무 지도 창과 메모 창은 거부한다.

단축키는 수정키 하나 이상과 일반 키 하나(`Ctrl+Alt+E` 형식)만 등록한다. `Alt+F4`, `Alt+Tab`, `Ctrl+Alt+Del`, `Win+L`, `Win+D`, `Ctrl+C/V/X/Z/A/S` 같은 시스템 조합은 거부한다. 패널 위치는 `bottom-right`와 `center`만. 웹뷰의 대화상자 권한은 뺐고, Rust 대화상자 플러그인 초기화는 그대로다.

남은 과제: 위의 tools.json 직접 수정 구멍. 도구 추가·수정과 끌어 온 바로가기는 대상을 tools.json에 저장하고, 실행은 도구 번호로만 한다.

## 사진 모자이크 자동 찾기

기기 안 기능: Windows에 들어 있는 얼굴 감지와 문자 인식을 이 PC에서만 사용한다. 사진, 찾은 영역, 인식한 글자는 밖으로 보내지 않고 저장하거나 로그로 남기지 않는다. 화면에는 영역 좌표와 종류만 간다.

영역 좌표: 사진을 한 장으로 읽은 뒤 이 프로그램이 조각을 잘라 감지기에 넘긴다. 0–1 좌표는 원본 가로·세로 기준이고, 미리보기와 저장이 같은 비율을 쓴다.

정확도 한계: 모든 얼굴과 숫자를 찾지 못한다. 옆모습, 작거나 가려진 얼굴, 흐린 글자는 빠질 수 있다. 한국어 문자 인식 팩이 없으면 숫자·글자 찾기를 끄고, 얼굴 찾기는 계속할 수 있다. 얼굴 감지를 쓸 수 없는 PC에서는 얼굴 찾기를 끈다. 찾은 후보는 확인한 뒤에만 새 파일로 저장한다.

이 파일이 작업 인계본이다. 채팅 기록보다 이 문서와 git을 따른다.

## 업무바통

홈의 업무 인수인계에서 폴더를 고르면 이 PC 안에서만 읽고, 월별 칸과 카드를 보여 준다. 분석 결과와 고친 내용은 저장을 누르기 전에는 앱 데이터에 넣지 않는다. 저장 JSON에는 절대 경로를 넣지 않고, 원본 폴더 안 저장은 거부한다. 원본 파일은 바꾸지 않는다.

AI 보조는 화면 안에서만 켜고, 기본은 꺼져 있다. 기관 내부 AI 서버 허용 여부를 정책으로 두는 확장 후보. 지금은 `127.0.0.1`만 연결한다. 포트·주소는 저장 JSON에 넣지 않고, 모델 이름과 제안 여부만 넣는다. 카드당 최근 수정 파일 3개, 파일당 앞 3,000자. 응답 상한 256KB, 요청 본문 상한 64KB, 기본 대기 90초. 주민번호 형식·휴대전화·계좌 후보·이메일은 보내기 전에 `[가림]`으로 바꾼다. 모델이 없거나 연결 확인 전이면 규칙 카드만 나온다. 설치 순서는 `docs/handover-ai-setup.md`. 모델은 설치본에 없다.

구형 HWP는 읽지 않는다. 안내 문장은 "구형 한글 문서는 읽지 않습니다. HWPX로 저장한 파일을 폴더에 넣어 주세요." `cfb` 0.7.3(MIT, 이미 간접 의존)과 `flate2` 1.1.10(MIT OR Apache-2.0, 이미 있음)을 직접 의존으로 넣어 구형 HWP 본문을 읽는 안은 아직 넣지 않는다. 가상 정답지에는 hwp가 없고, 암호·배포용 HWP는 그 안을 넣어도 실패할 수 있다. 실제 폴더에서 본문 기한이 빠지는 것이 확인된 뒤에 다시 정한다. 라이선스 본문은 읽지 않았고 라이선스 준수를 보장하지 않는다.

읽기 상한은 파일 5,000개, 깊이 12, 파일 50MB, 전체 3분이다. 넘기면 그때까지 읽은 파일로 카드를 만들고 안내 문장을 붙인다. 엑셀에서 날짜·시간 서식인 칸만 카드 읽기에서 YYYY-MM-DD로 바꾼다. 문서 검색의 기본 읽기는 숫자를 그대로 둔다. 1900과 1904 날짜 체계를 모두 본다.

가상 정답지는 `src-tauri/fixtures/work-handover/`이다. 실제 업무 자료는 넣지 않는다.

인계 박스는 `.edupack`이고 최상위 `kind`는 `work-handover`이다. 카드, 고른 바로가기 정의, 업무 폴더 표시, 고른 메모, 전임자 한마디를 담는다. 근거 파일은 상대 위치와 내용 해시만 있고, 해시가 다르면 "전임자가 넘긴 뒤 바뀐 파일입니다". `content_hash`는 박스가 깨졌는지 보는 용도이고, 누가 만들었는지 증명하는 서명이 아니다. 상한은 2MB, 카드 40, 바로가기 40, 메모 8이다. 바로가기는 고른 것만 넣고 같은 대상은 건너뛴다.

사용자 폴더(Known Folder Profile) 안의 업무 폴더 경로와 파일·폴더·프로그램 바로가기만 `%USERPROFILE%`로 바꿔 담고, 후임자 PC에서 그 사용자 폴더로 푼다. `D:\`와 `\\서버\...`는 그대로 두고 만드는 화면에 "이 경로가 그대로 전달됩니다"를 보여 준다.

후임자 화면 질문은 박스 문장과, 업무 폴더를 고른 뒤에는 그 폴더 본문을 메모리에서만 찾는다. 조각 길이 480자, 겹침 80자, 상위 5개. 점수는 세 글자 조각이 겹친 수×2와 단어가 들어 있는 수×20이다. 이번 달·다음 달 질문은 카드의 월과 기한으로 모델 없이 답한다. 근거가 없으면 "넘겨받은 자료에서 찾지 못했습니다"만 보여주고 모델을 부르지 않는다. 모델이 없거나 실패하면 "관련 내용을 찾았습니다"와 구절 목록만 보여 준다. 질문·답·조각·색인은 디스크에 쓰지 않는다.

## 다른 PC에서 열기

```bat
git clone https://github.com/golee75git/EduLanuncher.git
cd EduLanuncher
npm install
cd website
npm install
cd ..
```

필요 도구: Node 22+, Visual Studio 2022 Build Tools(C++), Rust(Tauri).

Cursor: 클론한 폴더를 **Open Folder**. `AGENTS.md`와 `.cursor/rules/`가 자동으로 붙는다. 채팅에 `@docs/HANDOFF.md` `@docs/PRD.md` `@docs/PLAN.md`를 넣으면 이 세션과 같다.

로컬 Cursor 대화(`agent-transcripts`)는 git에 없다. 복사하지 말고 위 문서를 쓴다.

## 명령

```bat
tauri-env.cmd dev
tauri-env.cmd build
npm run site:dev
npm run site:build
```

업무자료 검토 화면은 설치본 설정에 없다. 개발자만 `.\tauri-env.cmd dev` → 패널 → 오른쪽 위 톱니(설정) → 스크롤 「업무자료」→ 「검토가 필요한 업무자료」.

설치본 재빌드 규칙은 `.cursor/rules/rebuild-installer.mdc`와 `CLAUDE.md`.

- 같은 폴더에 `EduLauncher_YYYY-MM-DD_HHmm_x64-setup.exe` 복사
- git에 넣지 말고 GitHub Release에 업로드

## 웹 (Cloudflare)

프로젝트 이름: `edulanuncher`  
Root directory: **`website`** (비우면 런처 화면이 웹에 올라감). `/menu` 는 왼쪽에 편람 분류·업무자료·인증서, 오른쪽에 내용을 둔다. `/menu/topic/업무id` 와 `/menu/handbook` 분류·업무는 업무 흐름과 한눈에 보기를 사이트에서 그린다. 편람은 분류 그림의 칸 순서다. 단계 글은 `website/tools/copyKnowledge.mjs`가 업무자료 JSON에서 만든다.

루트 `package.json`·`vite.config.ts`에 wrangler나 `@cloudflare/vite-plugin`을 두지 않는다. 앱 `npm run build`는 패널만 묶는다. 사이트는 `npm run site:build`와 `website/wrangler.jsonc`만 쓴다.

| 항목 | 값 |
|---|---|
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` |
| Output | `dist` |

`website/wrangler.jsonc`: `main` = `src/worker/opinion.ts`, `assets.directory` = `./dist`, `not_found_handling` = `single-page-application`. `_redirects` 쓰지 않음.

의견 페이지는 `/opinion`이다. 계정은 없다. 글 저장은 D1 바인딩 `OPINION_DB`, 데이터베이스 `edulanuncher-opinion` (`076c0fba-dabc-48b9-a465-b36a152d3a1a`)이다. 공개 목록의 이름은 첫 글자만 보이고 뒤는 `**`이다. 한 글자는 그대로다. 글 관리는 메뉴에 없는 `/manage`이다. 같은 Worker 비밀 `OPINION_HIDE_KEY`로 숨긴 글을 포함해 입력한 이름을 보고, 다시 보이게 할 수 있다. 열쇠 값은 저장소에 넣지 않는다. 요청 수는 Cloudflare 대시보드 링크만 둔다.

`main` 푸시하면 배포. 사이트 다운로드 버튼은 GitHub Releases.

- 업무도구 「단축키」: Windows·문서 단축키 20개. 탐색기·잠금·설정·작업 관리자·화면 캡처는 이름을 누르면 연다. 키 전송 없음

- 확인됨: 개인정보 검사 전후 앱 데이터 폴더(Roaming, Local)에 크기 변화 없음. 가짜 파일 이름, 문구, 폴더명 흔적 없음.

Edge에서 `http://127.0.0.1:9222`를 열고 해당 페이지의 콘솔을 본다. CSP 위반 문장이 없으면 이상 없음이다. 포트가 열리지 않으면 그 항목은 계속 미확인이다.

2. 가짜 파일은 `cargo run --bin privacy_fixtures --features fixtures -- <폴더>`로 만든다. 개인정보 보호에서 고르거나 올려 등급을 확인한다. 기대는 명단은 높음, 연락처는 있음, 공문 바닥의 반복 대표번호는 발견되지 않음에 참고 안내, HWP와 손상 파일은 검사 불가이다.
3. 화면에 들어온 직후 놓은 파일은 검사 목록만, 뒤로 나간 뒤 홈에 놓은 파일은 바로가기, 화면을 연 채 트레이로 숨긴 뒤 다시 열어 다른 화면에 놓은 파일도 바로가기이다.
4. 미리보기를 연 다음 원본을 저장하고 다시 미리보기를 누르면 “파일이 바뀌어 다시 검사가 필요합니다.”가 나와야 한다.

보안 3단계에서 처리할 문제: `document_search`의 `walk_folder`와 본문 추출은 클라우드 전용 속성을 보지 않는다. OneDrive에 연결된 폴더를 색인하면 온라인 전용 파일 본문이 내려받아질 수 있다. 나중에 폴더 검사와 같은 `FindFirstFileExW` 판정을 써야 한다. 이번 단계에서는 `document_search`를 바꾸지 않았다.
