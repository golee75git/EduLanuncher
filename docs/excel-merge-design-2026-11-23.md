# 엑셀 통합·취합 설계 초안 (2026-11-23)

상태: 설계 초안. 구현 전. 코드 변경 없음.

## 1. 목적

같은 양식으로 받은 여러 엑셀 파일을 한 파일로 모은다. 학교 사무에서 부서·학년별로 받은 제출 파일을 합치는 일을 런처 안에서 끝내게 한다.

## 2. 1단계 범위: 세로 통합

- 입력: `.xlsx`, `.csv` 여러 개 (드롭 또는 선택)
- 동작: 각 파일의 첫 시트(선택 시 시트 이름 지정)를 읽어 첫 파일의 헤더 아래로 세로로 이어 붙인다
- 옵션: 맨 앞 열에 "원본 파일명" 열 추가 (기본 켬)
- 헤더 처리: 첫 파일의 첫 비어 있지 않은 줄을 헤더로 본다. 다른 파일은 헤더 이름으로 열을 맞추고, 없는 열은 빈칸, 헤더에 없는 열은 "맞추지 못한 열"로 알려 준다
- 출력: 새 `.xlsx` 한 개. 원본은 건드리지 않는다

2단계 후보 (이번 범위 아님): 고정 셀 취합(지정 셀 좌표만 뽑아 한 표), 시트 모으기.

## 3. 의존성

새 크레이트 없음. 이미 쓰는 `zip`, `quick-xml`만 쓴다.

- `.xls`(BIFF), `.xlsm` 매크로, 암호 걸린 파일은 지원하지 않는다. 안내 문구로 xlsx 저장을 요청한다.
- `calamine`, `rust_xlsxwriter`는 라이선스상 문제는 없으나(MIT/Apache) 이 저장소의 직접 구현 방침에 따라 쓰지 않는다. 나중에 바꾸면 도입 전에 크레이트명·버전·라이선스·출처·사유를 먼저 적는다.

## 4. 기존 리더 재사용 여부 (코드 확인 결과)

`src-tauri/src/site_list.rs`의 XLSX 리더(`sheet_table` 등)는 사이트 목록 전용이라 그대로 쓰면 맞지 않는다.

| 항목 | 현재 동작 | 통합에 필요한 것 |
|---|---|---|
| 시트 | 첫 시트만 | 첫 시트 기본, 시트 선택 가능 |
| 열 수 | `MAX_COLUMN = 32` | 더 넓게 (예: 200) |
| 행 수 | `MAX_ROWS = 300` (행 상한은 사이트 쪽 로직) | 파일당·전체 상한 별도 |
| 파일 크기 | 4MB | 파일당 상한 별도 (예: 20MB) |
| 수식 | `<f>` 글자가 `<v>` 값과 섞여 들어갈 수 있음 | `<v>` 캐시값만 읽기 |
| 날짜 | 시리얼 숫자 그대로 | 셀 서식(numFmt) 보고 날짜로 변환 |
| 문자 유형 | `t="s"`만 처리 | `inlineStr`, `str`, `b`, `e` 처리 |

결정: `site_list.rs`는 건드리지 않고(최소 diff, 다른 화면 무영향) 새 모듈 `excel_merge.rs`가 같은 방식(zip 엔트리 수·해제 크기 상한, 경로 검증)으로 자체 리더를 갖는다. zip 안전 도우미(`open_zip`, `read_part`, `safe_sheet_path`)는 중복이 커지면 `pub(crate)`로 열어 공유하는 것을 구현 단계에서 판단한다.

## 5. 안전 규칙

- 원본은 읽기 전용. 결과는 첫 파일 옆에 새 이름(`첫파일_통합.xlsx`, 있으면 `_2`…)으로 만들고 덮어쓰지 않는다. 기존 PDF 합치기(`pdf_merge`)와 같은 방식이며, 시스템 폴더는 `path_grant::output_dir_allowed`로 막는다. (handover는 폴더를 통째로 읽어서 출력을 원본 폴더 밖에 두게 했지만, 여기는 파일 단위라 이 규칙을 따르지 않는다)
- 경로는 `path_grant.rs`로 불투명 id와 표시 이름만 UI에 넘긴다
- 수식은 계산하지 않고 저장된 캐시값만 읽는다. 외부 링크는 따라가지 않는다
- 쓸 때 문자열이 `=`, `+`, `-`, `@`로 시작하면 문자열 셀로 저장한다 (수식 주입 방지)
- 앞자리 0(학번·전화번호), 긴 숫자는 문자열로 보존한다
- 병합 셀은 첫 셀 값만 남긴다
- 상한: zip 엔트리 수, 해제 크기 합계, 파일 개수, 전체 행·열 수. 넘으면 `limited`로 알리고 잘라서 처리한다
- 오류 메시지에 원본 경로나 셀 내용을 넣지 않는다 (기존 `site_list.rs` 방식)
- 출력 xlsx에는 매크로, 외부 링크, 개인정보성 문서 속성을 넣지 않는다

## 6. 구조

- Rust: `src-tauri/src/excel_merge.rs`
  - `merge_scan`: 파일별 시트 이름, 헤더, 행 수 미리보기
  - `merge_run`: 통합 실행, 결과 파일 id와 요약(합친 행 수, 건너뛴 파일, 맞추지 못한 열)
- 프론트: `src/services/excelMergeService.ts`, 페이지 1개, `excelDropGate.ts` (PDF 도구의 드롭 게이트와 같은 방식)
- 테스트: Rust 인라인 `#[cfg(test)]`. 테스트용 xlsx는 코드로 직접 만든 최소 파일만 쓴다

## 7. 구현 순서

1. 이 문서와 `IP_DESIGN_LOG.md` 항목 (이번 작업)
2. `excel_merge.rs` 읽기부 + 단위 테스트 (수식·날짜·inlineStr·병합 셀)
3. 결과를 새 xlsx 파일로 저장하는 기능(최소 OOXML) + 저장 후 다시 읽어 같은지 확인하는 테스트
4. `merge_scan`/`merge_run` 커맨드, `path_grant` 연결
5. 프론트 페이지와 드롭 연결
6. `RELEASE_IP_CHECKLIST.md` 갱신, 설치 파일 빌드 절차는 CLAUDE.md를 따른다

## 8. 열어 둔 질문

- 첫 시트만으로 충분한가, 시트 선택이 처음부터 필요한가
- 헤더가 여러 줄(제목 줄 + 헤더)인 양식이 흔한가. 그렇다면 "헤더 줄 번호" 입력이 필요하다
- 파일당 상한을 20MB로 둘지, 학교 PC 메모리를 고려해 더 낮출지
