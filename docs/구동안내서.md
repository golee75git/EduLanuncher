# 업무 인수인계 구동안내서

아무것도 설치되지 않은 Windows PC에서 교육업무 런처의 업무 인수인계를 시연할 때의 순서이다. 명령은 PowerShell에 그대로 붙여 넣는다.

모델이 없어도 규칙만으로 월별 시기와 기한 카드가 나온다. AI 모델은 선택이다. 모델은 설치 파일에 들어 있지 않다.

라이선스 준수를 보장하지 않는다. 받는 모델의 이용 조건은 그 모델의 공식 문서에서 확인한다.

## 1. 런처 설치

받을 파일 이름은 아래 둘 중 하나이다. 내용은 같다.

- `AILauncher_0.1.177-20261005_x64-setup.exe`
- `AILauncher_2026-10-05_1205_x64-setup.exe`

받기 주소:

```text
https://github.com/golee75git/EduLanuncher/releases/download/0.1.177-20261005/AILauncher_0.1.177-20261005_x64-setup.exe
```

받은 폴더에서 설치 파일을 두 번 누른다. 설치가 끝나면 트레이의 AILauncher를 누른다. 창 제목은 AI런처이다. 패널이 안 보이면 `Ctrl+Alt+E`를 누른다.

Windows가 "PC가 보호되었습니다"라고 하면, 이 PC가 설치 파일의 게시자를 아직 확인하지 못했다는 안내이다.

1. 창에서 "추가 정보"를 누른다.
2. 아래에 나타나는 "실행"을 누른다.
3. 설치 창의 안내를 따라 끝낸다.

이전 EduLauncher 설치가 있으면 제거한 뒤 이 파일로 설치한다. 바로가기 이름이 이미 AILauncher인 0.1.176은 그 위에 다시 설치하면 된다. 설치 폴더의 실행 파일은 AILauncher.exe이다.

## 2. AI 모델 준비 (선택)

규칙 카드는 이 단계를 하지 않아도 나온다. 이름·할 일·기관·날짜 제안이 필요할 때만 한다. 제안은 적용하기 전에는 업무 이름을 바꾸지 않는다.

1. [Ollama](https://ollama.com/) 공식 사이트에서 Windows용 설치 파일을 받아 설치한다.
2. PowerShell에서 모델 두 개를 받는다. 받는 동안 디스크를 쓰고 시간이 걸린다.

```powershell
ollama pull gemma3:4b
ollama pull exaone3.5:2.4b
```

3. 교육업무 런처에서 홈의 업무 인수인계를 연다.
4. AI 보조를 켠다. 포트는 `11434`로 둔다.
5. 모델 이름을 `gemma3:4b`로 두고 연결 확인을 누른다. `응답함`이 보이면 된다. 이 확인에는 문서 내용을 보내지 않는다.
6. 두 번째 모델과 비교할 때는 이름을 `exaone3.5:2.4b`로 바꾸고 연결 확인을 다시 누른다.

다른 모델을 받아도 된다. 이름과 이용 조건은 그 모델의 공식 문서를 본다.

## 3. 시연 폴더 준비

시연은 `업무바통_시연자료.zip`을 풀어 사용한다. 저장소에 있으면 `demo\업무바통_시연자료.zip`이다. 기관, 사람, 전화번호는 모두 가상이다.

1. 압축 파일을 두 번 누르거나, 풀 폴더를 정한 뒤 압축을 푼다.
2. 풀린 `folder`를 업무 폴더로 고른다.
3. 후임자 화면만 먼저 보여 줄 때는 같이 들어 있는 `시연-인계박스.edupack`을 두 번 누른다. 이 파일에는 사용자 폴더 경로가 없다.

`demo\make_demo_folder.py`는 개발용이다. 샘플을 다시 만들 때만 쓰고, 시연에서는 실행하지 않는다.

## 4. 시연 순서

말할 문장과 화면은 `docs\시연시나리오.md`를 따른다. 약 5분이다.

1. 전임자 화면에서 압축을 풀어 나온 `folder`를 고르고 분석을 본다.
2. 필요하면 첫 번째 모델의 제안 이름을 하나 적용하고, 카드 하나를 고친다.
3. 인계 박스를 만들 때 메모에 가짜 연락처를 넣고, 가려서 넣기가 기본인지 확인한 뒤 저장한다.
4. 후임자 화면에서 이번 달 업무, 질문 두 개, 바로가기를 본다.
5. 두 번째 모델로 아직 확인하지 않은 제안만 다시 받아 비교한다.

## 5. 문제가 생겼을 때

연결이 안 될 때

- AI 보조가 꺼져 있으면 규칙 카드만 나온다. 시연은 그 상태로도 된다.
- 포트가 `11434`인지 본다. 주소는 이 PC의 `127.0.0.1`만 허용한다.
- PowerShell에서 `ollama pull gemma3:4b`가 끝났는지 본다. 모델 이름이 화면과 같은지 본다.
- "연결하지 못했습니다"가 나오면 Ollama가 켜져 있는지 확인한 뒤 연결 확인을 다시 누른다.

느릴 때

- 한 번 요청은 약 90초를 넘기면 멈춘다. 화면의 중지는 그때까지 모은 제안만 남긴다.
- 더 작은 모델을 쓰면 더 빨리 답한다.
- AI 보조를 끄면 규칙으로 만든 카드만 바로 나온다.

한국어 글자 인식이 없을 때

- 이것은 사진 모자이크의 글자 찾기이다. 업무 인수인계 카드와는 별개이다.
- Windows에 한국어 문자 인식 팩이 없으면 숫자·글자 찾기를 끄고, 얼굴 찾기는 계속할 수 있다.
- 설정에서 한국어 언어 기능을 설치한 뒤 사진 모자이크를 다시 연다.

구형 한글(HWP)일 때

- 구형 한글 문서는 읽지 않는다. 화면에는 "구형 한글 문서는 읽지 않습니다. HWPX로 저장한 파일을 폴더에 넣어 주세요."가 나온다.
- 한글 프로그램에서 HWPX로 다시 저장한 파일을 같은 폴더에 넣는다. 시연 폴더에는 HWPX만 있고 구형 HWP는 없다.

## 6. 개인정보·보안

- 고른 업무 폴더만 이 PC 안에서 읽는다. 원본 파일은 바꾸지 않는다.
- 분석 결과는 저장을 누르기 전에는 앱 데이터에 넣지 않는다. 저장해도 원본 폴더 안에는 넣지 않는다.
- AI를 켜도 `127.0.0.1`로만 보내고, 주민번호 형식·휴대전화·계좌 후보·이메일은 `[가림]`으로 바꾼 뒤 보낸다.
- 후임자 질문의 조각과 색인, 질문과 답은 디스크에 쓰지 않는다. 화면을 떠나면 지운다.
- 근거가 없으면 모델을 부르지 않고 "넘겨받은 자료에서 찾지 못했습니다"만 보여 준다.
- 인계 박스의 내용 해시는 파일이 깨졌는지 보는 용도이고, 누가 만들었는지 증명하는 서명이 아니다.
- 사용자 폴더 안 경로는 `%USERPROFILE%`로 바꿔 넘긴다. 그 밖 경로에는 "이 경로가 그대로 전달됩니다"가 나온다.
