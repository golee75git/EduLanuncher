# 창 앞에 고정 — 설계안

- 작성일: 2026-11-25
- 상태: 2026-11-25 승인, 구현함(커밋·설치본 전, 앱 화면에서 직접 확인 전)
- 크기: 작은 변경 (새 화면 1개, Rust 모듈 1개)

## 목적

이 PC에 열려 있는 파일 탐색기, 브라우저 강의 창, 동영상 플레이어 같은 창을 런처에서 골라 다른 창보다 앞에 고정한다.

## 접근 방법

| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 목록에서 고르기 (선택)** | 고정 상태가 보이고 해제가 쉽다 | 런처를 열어야 한다 |
| B. 단축키 | 가장 빠르다 | 단축키를 외워야 하고 상태가 안 보인다 |
| C. A + B | 둘의 장점 | 만들고 시험할 것이 늘어난다 |

2026-11-25에 A를 선택했다. B는 이번 범위에 넣지 않는다.

## 화면

컴퓨터도구에 「창 앞에 고정」 항목을 추가한다. 홈 검색에서도 `창 고정`, `항상 위`, `맨 앞`, `창 앞에`로 찾는다.

```
창 앞에 고정                      [새로 고침] [모두 해제]
─────────────────────────────────────────────
[아이콘] 원격연수 강의실 - Edge                  [해제]
         msedge · 고정 중
[아이콘] 동영상 플레이어                         [고정]
         player
[아이콘] 다운로드                                [고정]
         explorer
```

- 목록은 화면에 들어올 때, `새 로 고침`을 누를 때, 런처 창이 다시 초점을 받을 때 읽는다. 주기적으로 반복해 읽지 않는다.
- 여러 창을 동시에 고정할 수 있다. 겹치면 마지막에 누른 창이 위에 온다.
- 열린 창이 없으면 「고정할 창이 없습니다.」를 보인다.

## 동작

1. **목록 대상:** 화면에 보이거나 최소화된 일반 창 중 제목이 있는 것. 런처 자신의 창, 바탕화면·작업 표시줄, 보조 도구 창, Windows가 숨겨 둔 창은 뺀다. 최대 60개, 제목은 120자까지.
2. **고정:** 최소화되어 있으면 원래 크기(최대화 포함)로 다시 띄운 뒤 항상 위로 둔다. 창의 위치와 크기는 바꾸지 않는다.
3. **확인:** 바꾼 뒤 실제로 적용됐는지 확인한다. 안 됐으면 「이 창은 고정하지 못했습니다. 관리자 권한으로 실행한 창은 고정할 수 없습니다.」를 보인다.
4. **응답 없는 창:** 건드리지 않고 안내한다.
5. **사라진 창:** 누른 사이에 닫혔으면 「창이 닫혔습니다.」를 보이고 목록을 다시 읽는다.
6. **다른 곳에서 항상 위로 둔 창:** 「항상 위」로 표시하고 `해제`를 둔다. 사용자가 누를 때만 해제한다. 런처가 비정상 종료해 고정이 남은 경우도 여기서 풀 수 있다.
7. **런처 창:** 고정한 창이 하나라도 있으면 런처 패널도 항상 위로 두어, 고정한 창에 가려 해제를 못 하는 일이 없게 한다. 고정이 모두 풀리면 설정의 원래 값으로 돌린다. 설정값 자체는 바꾸지 않는다.
8. **해제 범위:** `모두 해제`와 런처 종료(트레이 종료, 업데이트 설치 포함)는 런처가 고정한 창만 해제한다. 패널을 닫아 트레이로 보내는 것은 고정을 유지한다.
9. **저장:** 아무것도 저장하지 않는다. 런처를 다시 켜면 고정 목록은 비어 있다.

## 구현 구조

- `src-tauri/src/window_pin.rs` (새 파일, Windows 전용)
  - 명령: 목록 읽기, 창 하나 고정/해제, 모두 해제. `main` 창에서만 받는다.
  - 화면에는 임의 id, 창 제목, 프로그램 이름, 아이콘, 상태만 넘긴다. 창 핸들과 실행 파일 경로는 Rust 안에 둔다.
  - 바꾸기 전에 id의 창이 같은 프로세스의 창인지 다시 확인한다.
  - 아이콘은 기존 `shell_icon::png_data_url`을 쓴다.
- `src-tauri/src/lib.rs`: 모듈·명령 등록, 종료 시 해제 처리, 패널 항상 위 값 맞추기.
- `src-tauri/Cargo.toml`: 새 라이브러리는 없다. 숨은 창을 가려내려고 기존 `windows`의 `Win32_Graphics_Dwm` 기능만 켠다.
- 프런트: `src/pages/WindowPinPage.tsx`, `src/services/windowPinService.ts` 추가. `computerTools.ts`, `ComputerToolPage.tsx`, `App.tsx`에 연결(홈 검색은 항목의 이름·설명으로 찾으므로 `HomePage.tsx`는 바꾸지 않음).
- `docs/IP_DESIGN_LOG.md`에 출처 항목 추가.

## 하지 않는 것

- 단축키 고정, 마우스로 창 찍어 고르기
- 창 이동·크기 조절·투명도 조절
- 강의 사이트의 초점 감지나 일시정지를 우회하는 기능
- 키 입력·마우스 입력 대신 보내기, 창 내용 읽기·캡처
- 창 제목을 저장하거나 밖으로 보내기

## 알려진 한계

- 관리자 권한으로 실행한 창은 고정되지 않을 수 있다.
- 전체 화면 프로그램은 고정한 창을 가릴 수 있다.
- 일부 Windows 앱은 아이콘이 기본 모양으로 보일 수 있다.

## 확인 방법

- Rust 단위 시험: 목록 대상 판별, 제목 자르기, id와 프로세스 대조, 해제 대상 선택.
- `npm run build`, `cargo test`.
- 이 PC에서 직접: 탐색기·브라우저·플레이어 고정과 해제, 최소화 창, 닫힌 창, 관리자 권한 창, 최대화한 창을 고정한 상태에서 런처 열기, 트레이 종료 후 해제 여부.

설치 파일 빌드와 GitHub Release 업로드는 구현 확인 후 따로 정한다.
